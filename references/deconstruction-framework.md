# 六层拆解框架详解

本文是 `ai-product-deconstruction` Skill 的核心方法参考。每一层都包含：**要解决的核心问题 → 关键调研动作 → 产出物 → 常见追问**。

## 拆解的核心主线

把产品当作一个"虚拟团队"拆解：

- **前台**：用户看到的是什么（输入框 / 画布 / 对话 / 表单卡片）。
- **后台**：一条多智能体管线（主 Agent + 专业角色 Agent 协作）。
- **主线问题**：*人类团队的分工，如何映射为 Agent？*

## 层级关系图

```text
市场层 ── 值不值得进？什么时候进？
  │
商业层 ── 是不是好生意？怎么赚钱？怎么冷启动？
  │
用户层 ── 用户真正要完成的任务是什么？替代了什么工作流？
  │
技术层 ── 团队分工如何映射为 Agent？主 Agent / 角色 Agent / HITL
  │
模型层 ── 哪些环节靠强模型？哪些靠流程设计聪明？模型路由？
  │
基础层 ── 靠什么数据与知识持续变强？
```

---

## 层 0 · 产品速览

**核心问题**：它到底是什么？用一句话说清楚。

| 调研动作 | 产出 |
|---|---|
| 官网首页 | 一句话定位 |
| 产品介绍页 / Demo | 产品构成（前台入口 + 后台管线） |
| 创始人访谈 / 媒体报道 | 面向用户、成立背景 |

**常见追问**：

- 它把自己定义为"工具"、"平台"还是"Agent 团队"？
- 它的目标用户画像（小白 / 半专业 / 专业）？
- 典型应用场景有几个、分别是什么？

---

## 层 1 · 市场层

**核心问题**：**赛道是否值得进入，什么时候进入？**

| 调研动作 | 产出 |
|---|---|
| 看市场研报、行业数据 | 市场盘子、增速、窗口期 |
| 政策 / 平台动向 | 是否"元年"、是否有激励政策 |
| 竞争格局分析 | 分层（工具/平台/模型厂商） |

**常见追问**：

- 市场有多大？制作成本/周期下降幅度？
- 竞品分几层？每层的核心打法是什么（垂直 vs 通用、效率 vs 质量）？
- 是否存在"爆款率 / 头部集中度"等关键指标？
- **是否立项的决策动作**：值得进吗？何时进？

---

## 层 2 · 商业层

**核心问题**：**这是一个什么样的生意/机会？如何收获第一批种子用户？**

| 调研动作 | 产出 |
|---|---|
| 看官网介绍 | 定价梯度、套餐权益 |
| 看创始人访谈 | 商业逻辑、冷启动故事 |

**常见追问**：

- 变现方式：订阅 / 按量付费 / 打包卖 / 混合？
- 定价梯度如何设计（免费版 → 高价版的能力阶梯）？
- 成本结构（显卡/算力成本 vs 订阅收入）？
- **护城河**：是模型？还是工艺知识 + 多模型编排能力 + 数据？
- 如何收获第一批种子用户（内测排队、社区、KOL 传播）？

---

## 层 3 · 用户层

**核心问题**：**用户真正完成的任务是什么？它替代了以前什么工作流？**

> 关键原则：**没有真实决策动作，都是伪需求。** 必须真实体验。

| 调研动作 | 产出 |
|---|---|
| 按场景深度体验（真实跑一遍端到端） | 用户旅程图（正向 + 逆向/异常） |
| 记录每一步交互 | 完整输出物及分数 |
| 设计测试场景 | 能力维度评测表 |

**常见追问**：

- 交互入口在哪（聊天框 / 画布 / 流程连线）？输入什么、输出什么？
- 如何降低上手难度（靠 Prompt 还是 UI 引导）？
- 为什么不像其他同类产品那样提供某些能力（差异判断）？
- 托管模式 vs 对话模式如何为不同用户服务？能否串联？

---

## 层 4 · 技术层

**核心问题**：**人类团队的分工，如何映射为 Agent？**

| 调研动作 | 产出 |
|---|---|
| 拆背后 Agent 组成 | 技术流程图 |
| 逐个 Agent 拆解 | 每个 Agent 四件套（逻辑/构成/工具/提示词） |

**先判断**：背后是 Workflow / 单 Agent / Multi-Agent？有没有接 RAG？接了哪些外部插件？

**Agent 拆解四件套**（每个 Agent 必须输出）：

### 4.1 逻辑梳理
- 输入 → 处理 → 输出，画出分支与人工介入点。
- 标注：哪些环节允许 human 介入（推送 UI 卡片等待确认）？

### 4.2 构成推导
判断该 Agent 适合哪种架构：

| 模式 | 特点 | 适用 |
|---|---|---|
| ReAct | 探索、对话式开放任务；推理出错产生大量中间 Token 自我修正 | 需要不断获取外部信息、修正动作 |
| Planner-Executor | 生产、长链路高耦合；字段更新做状态管理；支持审批流与断点续传 | 强状态管理的生产任务 |

### 4.3 可用工具推导
常见工具类型：

- RAG / 检索（风格库、知识库、影视专业知识）
- 上下文管理（全局字段读写，项目 PRD 式）
- 状态管理（确认/修改/质疑/新需求，回滚到稳定节点）
- 表单工具（基础设置、模型选择、风格选择、情绪词选择等 UI 卡片）
- 追问工具（补全缺失信息）
- 调度工具（任务下发给其他 Agent）
- 专业工具（计价、成本估算、提示词生成、音视频生成）

### 4.4 提示词推导
按固定结构推导该 Agent 的 System Prompt：

1. 角色定义（Role）
2. 输入契约（Input Contract：读哪些字段）
3. 输出契约（Output Contract：写哪些字段、禁止触碰哪些字段）
4. 硬约束（Hard Constraints：严禁跨步、禁止幻觉、引用完整性、必须走表单）
5. 任务处理流程（Workflow：Step A→F，含状态回置）
6. 工具调用规范（Tool Instructions：每个工具的原则）
7. 输出格式（Response Format：严格 JSON 契约）

**技术层常问问题**：

- 如何解决全局一致性（角色/场景一致性）？→ 全局上下文工程：增删改查、强引用关系
- 哪里需要 human in the loop？如何设计？
- 如何在 System Prompt 里划清能力边界？
- 如何防止违规、IP 侵权？

---

## 层 5 · 模型层

**核心问题**：**哪些环节必须依赖强模型？哪些只是流程设计聪明？**

| 调研动作 | 产出 |
|---|---|
| 拆解单个 Agent 的模型调用 | 模型路由逻辑 |
| 收集模型能力信息 | 模型列表 + 核心优势 + 适用场景 |

**常见追问**：

- 模型列表（生图 / 视频 / 文本 / 音频）各有哪些？
- 每个模型的核心优势与推荐场景（物理模拟、长时长、运镜、特效、速度）？
- 路由逻辑：如何与风格库匹配 + 场景灵活调用？
- 模型和流程的优势是否会随着数据积累越用越强？

---

## 层 6 · 基础层

**核心问题**：**它靠什么数据与知识持续变强（壁垒）？**

| 调研动作 | 产出 |
|---|---|
| 分析调用的数据 | 数据内容清单（剧本、角色、用户反馈、模型表现） |
| 分析调用的模型 | 数据来源说明 |
| 梳理知识库 | 知识库结构图 |

**常见追问**：

- 知识库构成（风格库、视频知识库、内置专业知识、模型表现得分）？
- 全局上下文的一致性协议：所有 Agent 是否共享一套标准 Schema？
- 视觉与情绪的映射：如何把模糊情绪转化为模型可理解的视觉参数？
- 风格库动态维护：新模型引入后是否重新评测适配度？

---

## 层 7 · 架构总结

**动作**：汇总各层，画分层架构图（应用层 → Agent 层 → 模型层 → 基础层）。

**文字总结要点**：产品把"什么团队 / 什么流程"装进了平台，表层体验是什么，底层机制是什么，真正的壁垒沉淀在哪一层。
