# 🔍 AI 产品拆解工作流 Skill

> 把"拆解一个 AI 产品 / Multi-Agent 平台"沉淀为可复用、可验证的标准工作流。
>
> 技术每 3 个月就大变样，**唯有拆解与还原的底层思考框架是永恒的。**

---

## ✨ 这是什么

一个用于**深度拆解 AI 产品 / Agent 平台**的开源 Skill。它把"看清一个产品本质"的方法论封装成 **6 层拆解框架**，每层回答固定的核心问题并产出固定产物，最终输出结构化的拆解报告。

```text
市场层 → 商业层 → 用户层 → 技术层 → 模型层 → 基础层
```

### 适用场景

- 🎯 **竞品分析**：深入理解竞争对手的产品定位、商业模式和技术架构
- 📊 **产品研究**：系统拆解一个 AI 产品，看清它的本质和核心竞争力
- 🏗️ **架构学习**：理解 Multi-Agent 平台的团队分工映射、模型路由和数据资产
- 💡 **立项决策**：判断一个赛道是否值得进入，什么时候进入
- 📝 **面试准备**：用结构化框架回答"你怎么看 XX 产品"类面试题

---

## 🎯 六层拆解框架

| 层级 | 核心问题 | 产出物 |
|------|---------|--------|
| **0. 产品速览** | 它到底是什么？ | 一句话定位、产品构成、场景清单 |
| **1. 市场层** | 赛道是否值得进入，什么时候进入？ | 竞品分析报告、是否立项决策 |
| **2. 商业层** | 这是一个什么样的生意/机会？ | 一句话定位、商业模式、护城河 |
| **3. 用户层** | 用户真正完成的任务是什么？ | 用户旅程图、能力评测表与分数 |
| **4. 技术层** | 团队分工如何映射为 Agent？ | 技术流程图、逐 Agent 四件套 |
| **5. 模型层** | 哪些环节靠强模型？ | 模型路由逻辑、选择理由 |
| **6. 基础层** | 靠什么数据与知识变强？ | 数据内容、数据来源、知识库结构 |

### 逐 Agent 四件套（技术层核心）

拆解每个 Agent 时，必须回答四个问题：

1. **逻辑梳理**：这个 Agent 的核心职责和决策逻辑是什么？
2. **构成推导**：它需要哪些子能力和知识？
3. **工具推导**：它需要调用哪些工具和 API？
4. **提示词推导**：它的系统提示词应该怎么写？

## 🚀 怎么使用

### 方式一：作为 Skill 使用（推荐）

1. 下载本仓库到本地
2. 将 `ai-product-deconstruction` 文件夹放到你的 `.user_skills` 目录下
3. 对 AI 说"帮我拆解 XX 产品"或"分析一下 XX Agent 平台"，AI 会自动触发本 Skill

### 方式二：手动参考模板

1. 复制 `templates/deconstruction-template.md` 作为起点
2. 按照 `SKILL.md` 中的六层框架逐步执行
3. 参考 `examples/oiioii-deconstruction.md` 完整示例

### 使用流程

1. **读取 `SKILL.md`**，理解六层框架和质量门要求
2. **产品速览**：先用一句话说清这个产品是什么
3. **逐层拆解**：从市场层到基础层，每层先回答核心问题，再产出对应产物
4. **过质量门**：每层完成后检查是否满足质量门要求
5. **架构总结**：最后输出全局架构总结和核心洞察

## 💡 核心理念

### 1. 拆解不是罗列，是还原

> 拆解一个产品，不是把它的功能列出来，而是还原它**为什么这么设计**、**背后的思考是什么**、**如果是我会怎么做**。

### 2. 六层框架是思考的脚手架

> 六层框架不是束缚，而是确保你不会遗漏关键维度。熟练之后可以灵活调整顺序，但新手建议严格按框架走。

### 3. 每个结论都要有证据

> 拆解报告中的每一个判断，都必须有产品实际功能、公开资料或逻辑推理支撑。不做无根据的猜测。

### 4. 重点是 Agent 映射

> AI 产品拆解的核心是技术层：**人类团队分工如何映射为 Agent**。这是 AI 产品和传统产品最大的区别。

## 📊 效果评测

拆解完成后，可以按照 `references/evaluation-method.md` 中的评测维度对拆解质量打分：

| 维度 | 权重 | 说明 |
|------|------|------|
| 完整性 | 25% | 六层框架是否全覆盖 |
| 深度 | 25% | 是否还原了背后的思考，而不只是罗列 |
| 证据支撑 | 20% | 每个结论是否有证据 |
| Agent 映射 | 20% | 技术层的 Agent 四件套是否到位 |
| 架构总结 | 10% | 是否提炼了可复用的洞察 |
